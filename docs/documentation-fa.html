مستندات پروژه docker-anywhere

راهنمای کامل فارسی — عامل اجرای دستور از راه دور با ارتباط خروجی‌محور (Outbound-Only) برای مدیریت Docker و سرور تولید

خلاصه یک‌خطی: این پروژه دو بخش دارد: عامل (Agent) روی سرور تولید نصب می‌شود و فقط به بیرون درخواست می‌زند؛ و سرور کنترل (Control Server) که دستورات را در صف قرار می‌دهد و نتایج را ذخیره می‌کند. هیچ پورتی برای دریافت دستور از اینترنت روی سرور تولید باز نمی‌شود.

۱. معرفی کلی پروژه

پروژه docker-anywhere یک سیستم مدیریت از راه دور برای سرورهای تولید است که با Python، فریم‌ورک FastAPI و ابزار UV ساخته شده است.

مشکل قبلی: اگر روی سرور تولید یک API ورودی باز کنید (مثلاً POST /execute)، هر حمله‌گر می‌تواند سعی کند به آن وصل شود. این ریسک امنیتی بالایی دارد.

راه‌حل این پروژه:

  • عامل (Agent) روی سرور تولید هر ۱۵ ثانیه (قابل تنظیم) به سرور کنترل وصل می‌شود و می‌پرسد: «دستور جدیدی دارم؟»
  • اگر دستوری باشد، فقط دستورات از پیش تأیید‌شده (Whitelist) اجرا می‌شوند.
  • نتیجه (stdout، stderr، returncode) به سرور کنترل برگردانده می‌شود.
  • اپراتور از طریق سرور کنترل دستور می‌فرستد و تاریخچه را می‌بیند.

دو پوشه اصلی

پوشه کجا اجرا می‌شود؟ نقش
agent/ روی هر سرور تولید دریافت دستور از صف، اجرای امن، گزارش نتیجه — فقط ارتباط خروجی
control_server/ روی یک سرور مرکزی / ابر صف دستورات، احراز هویت اپراتور و عامل، تاریخچه اجرا

۲. معماری و جریان کار

┌─────────────┐ HTTPS (امضا شده) ┌──────────────────┐ │ اپراتور │ ─── POST /api/v1/commands ───────► │ Control Server │ │ (Operator) │ ◄── GET /api/v1/history ──────── │ سرور کنترل │ └─────────────┘ └────────┬─────────┘ │ هر ۱۵ ثانیه (Outbound) │ ┌─────────────┐ GET /api/v1/poll (امضا شده) │ │ Agent │ ◄───────────────────────────────────────────┘ │ سرور تولید │ │ │ ─── POST /api/v1/results ───────────────────► └─────────────┘ فقط /health روی 127.0.0.1 (محلی) — نه برای دستور از اینترنت
  1. اپراتور با کلید مخصوص خودش، دستور «ری‌استارت سرویس web» را به صف عامل می‌فرستد.
  2. عامل در چرخه بعدی polling، دستور را می‌گیرد.
  3. ماژول executor.py دستور را به آرگومان‌های امن subprocess تبدیل می‌کند (بدون shell=True).
  4. نتیجه اجرا به سرور کنترل ارسال و در تاریخچه ثبت می‌شود.

۳. پوشه agent/ — عامل روی سرور تولید

این پوشه قلب سیستم روی سرور تولید است. تمام فایل‌های زیر با هم کار می‌کنند:

agent/main.py نقطه ورود

کار: اپلیکیشن FastAPI را راه‌اندازی می‌کند.

  • در startup: لاگ را تنظیم می‌کند و poller (حلقه polling) را شروع می‌کند.
  • در shutdown: poller را متوقف می‌کند.
  • اندپوینت GET /health: فقط برای مانیتورینگ محلی (مثلاً systemd) — وضعیت عامل، آخرین poll، تعداد دستورات اجراشده.
  • اندپوینت GET /: پاسخ ساده برای اطمینان از زنده بودن پروسه.

مهم: هیچ اندپوینتی برای «اجرای دستور از راه دور» وجود ندارد. فقط /health است.

agent/config.py تنظیمات

کار: تمام تنظیمات را از فایل agent/.env با Pydantic Settings v2 می‌خواند.

متغیرمعنی
AGENT_IDشناسه یکتا این سرور (مثلاً prod-server-01)
API_KEYکلید API مشترک با سرور کنترل
HMAC_SECRETرمز امضای درخواست‌ها
CONTROL_SERVER_URLآدرس سرور کنترل (باید HTTPS در تولید)
POLL_INTERVAL_SECONDSفاصله polling (پیش‌فرض ۱۵ ثانیه)
DOCKER_COMPOSE_FILEمسیر فایل docker-compose.yml
DOCKER_WORK_DIRپوشه کاری دستورات Docker
ALLOWED_SCRIPTS_DIRپوشه اسکریپت‌های مجاز برای run_script
REBOOT_CONFIRMATION_TOKENتوکن اجباری برای reboot سرور
COMMAND_TIMEOUT_SECONDSحداکثر زمان اجرای دستور
LOG_FILEمسیر فایل لاگ ممیزی
HEALTH_HOST / HEALTH_PORTآدرس محلی سرویس health (پیش‌فرض 127.0.0.1:8080)

agent/models.py ساختار داده

کار: مدل‌های Pydantic برای اعتبارسنجی JSON بین عامل و سرور کنترل.

  • ActionType: enum دستورات مجاز (docker_restart، docker_logs، server_reboot، ...)
  • CommandPayload: بدنه دستور دریافتی از poll
  • ExecutionResult: نتیجه اجرا برای ارسال به سرور کنترل
  • HealthResponse: پاسخ اندپوینت /health
  • CommandStatus: pending، running، success، failed، rejected

agent/security.py امنیت

کار: لایه امنیتی ارتباطات و لاگ ممیزی.

  • setup_logging(): لاگ به فایل + کنسول
  • audit_event(): ثبت رویدادهای امنیتی به صورت JSON در لاگ
  • signed_headers() / signed_request(): امضای HMAC-SHA256 هر درخواست خروجی
  • هدرها: X-API-Key، X-Timestamp، X-Nonce، X-Signature
  • RateLimiter: محدودیت نرخ برای /health (جلوگیری از سوءاستفاده محلی)

فرمت امضا: رشته کاننیکال از timestamp، nonce، method، path و hash بدنه — سپس HMAC با secret.

agent/executor.py اجرای دستور

کار: تنها جایی که دستور واقعاً روی سرور اجرا می‌شود — با قوانین سختگیرانه.

  • _build_command(): هر action را به لیست argv ثابت تبدیل می‌کند (مثلاً docker compose restart web)
  • نام سرویس Docker فقط حروف، عدد، خط تیره و زیرخط — با regex
  • run_script: فقط فایل‌های داخل ALLOWED_SCRIPTS_DIR و قابل اجرا — بدون path traversal
  • server_reboot: فقط اگر confirmation_token در params با تنظیمات یکی باشد
  • _run_subprocess(): asyncio + timeout — هرگز shell=True
  • خروجی بیش از حد مجاز truncate می‌شود
  • execute_command(): نقطه ورود اصلی — همیشه ExecutionResult برمی‌گرداند

agent/poller.py حلقه polling

کار: تسک پس‌زمینه asyncio که عامل را زنده نگه می‌دارد.

  • AgentPoller.start(): کلاینت httpx و تسک پس‌زمینه را می‌سازد
  • هر دوره: GET /api/v1/poll?agent_id=... → اگر دستور بود → execute → POST /api/v1/results
  • در صورت خطا: backoff نمایی (حداکثر ۵ دقیقه)
  • وضعیت برای /health: last_poll_at، commands_executed و غیره
  • شیء سراسری poller در main.py استفاده می‌شود

agent/.env.example

نمونه فایل محیط — کپی به .env و مقادیر واقعی را پر کنید. هرگز .env را commit نکنید.

agent/agent.service

فایل نمونه systemd برای اجرای دائمی عامل به عنوان سرویس سیستم، با hardening امنیتی (NoNewPrivileges، ProtectSystem و ...).

agent/__init__.py

فایل خالی پکیج — علامت می‌دهد agent یک ماژول پایتون است.

۴. پوشه control_server/ — سرور کنترل

سرور مرکزی که اپراتور و عامل‌ها با آن صحبت می‌کنند. در نسخه فعلی داده‌ها در حافظه (in-memory) است — برای تولید واقعی باید دیتابیس اضافه شود.

control_server/main.py API سرور کنترل

اندپوینت‌ها:

متد و مسیرچه کسی صدا می‌زند؟کار
GET /health هر کسی سلامت سرور کنترل
POST /api/v1/commands اپراتور (کلید Operator) قرار دادن دستور در صف عامل مشخص
GET /api/v1/poll عامل (کلید Agent) برداشتن یک دستور pending از صف
POST /api/v1/results عامل ثبت نتیجه اجرا در تاریخچه
GET /api/v1/history اپراتور مشاهده تاریخچه دستورات (فیلتر agent_id، limit)

دو صف مجزا از نظر احراز هویت: Operator برای فرستادن دستور / تاریخچه — Agent برای poll و result.

control_server/config.py

تنظیمات از control_server/.env:

  • AGENT_API_KEY / AGENT_HMAC_SECRET — باید با API_KEY و HMAC_SECRET عامل یکی باشد
  • OPERATOR_API_KEY / OPERATOR_HMAC_SECRET — فقط برای اپراتور
  • MAX_TIMESTAMP_SKEW_SECONDS — تحمل اختلاف ساعت (جلوگیری از replay)
  • RATE_LIMIT_* — محدودیت درخواست

control_server/security.py

آینه agent/security.py برای سمت سرور:

  • بررسی API key با compare_digest (ضد timing attack)
  • اعتبارسنجی timestamp و nonce (ضد replay)
  • محاسبه مجدد HMAC و مقایسه با X-Signature
  • RateLimiter بر اساس IP

control_server/models.py

  • PushCommandRequest: بدنه درخواست اپراتور برای صف کردن دستور
  • QueuedCommand: دستور در صف داخلی
  • HistoryEntry / HistoryResponse: خروجی تاریخچه
  • از مدل‌های agent.models برای ActionType و ExecutionResult استفاده مجدد می‌کند

control_server/cli.py

ابزار خط فرمان برای اپراتور — بدون نوشتن کد، دستور امضا‌شده به سرور می‌فرستد:

uv run python -m control_server.cli push \
  --url http://localhost:8000 \
  --agent-id prod-server-01 \
  --action docker_restart \
  --service web

نیاز به متغیرهای محیطی OPERATOR_API_KEY و OPERATOR_HMAC_SECRET دارد.

control_server/.env.example

نمونه تنظیمات سرور کنترل — کپی به .env و مقادیر امن تولید کنید.

۷. نکات امنیتی

  • عامل فقط به بیرون وصل می‌شود — پورت دستور از اینترنت باز نیست.
  • /health فقط روی 127.0.0.1 — از بیرون دیده نمی‌شود.
  • هر درخواست با API key + HMAC امضا می‌شود.
  • Nonce و timestamp از replay جلوگیری می‌کنند.
  • هیچ دستور دلخواهی اجرا نمی‌شود — فقط whitelist.
  • subprocess بدون shell — تزریق shell ممکن نیست.
  • کلیدها را با openssl rand -hex 32 بسازید؛ فایل .env را chmod 600 کنید.
  • در تولید: Control Server حتماً پشت HTTPS (مثلاً Nginx + Let's Encrypt).
  • کاربر عامل را به گروه docker اضافه کنید؛ reboot فقط با sudo محدود.

۸. نحوه اجرا با UV

نصب وابستگی‌ها

cd docker-anywhere
uv sync

سرور کنترل

cp control_server/.env.example control_server/.env
# ویرایش .env
uv run uvicorn control_server.main:app --host 0.0.0.0 --port 8000

عامل روی سرور تولید

cp agent/.env.example agent/.env
# API_KEY و HMAC_SECRET = AGENT_API_KEY و AGENT_HMAC_SECRET سرور کنترل
uv run uvicorn agent.main:app --host 127.0.0.1 --port 8080

فرستادن دستور

export OPERATOR_API_KEY=...
export OPERATOR_HMAC_SECRET=...
uv run python -m control_server.cli push \
  --agent-id prod-server-01 --action docker_status --service web

systemd

sudo cp agent/agent.service /etc/systemd/system/secure-agent.service
sudo systemctl enable --now secure-agent

۹. افزودن دستور جدید

  1. مقدار جدید به ActionType در agent/models.py اضافه کنید.
  2. شاخه جدید در _build_command() داخل agent/executor.py — فقط argv ثابت با ورودی validate‌شده.
  3. از CLI یا API سرور کنترل دستور را با action جدید بفرستید.

هرگز رشته shell خام از شبکه قبول نکنید. همیشه به لیست آرگومان ثابت map کنید.
